## 실제 LH 조회

`python main.py --dry-run` 성공:

- 기간: 2026-07-18~2026-10-16, 게시일 기준, 전체 상태.
- 전체 85건, 페이지당 100건으로 1페이지.
- 정확한 경기도 63건. 나머지 22건은 지역 필드 `인천광역시 외`로 제외.
- DB 파일 생성/초기화/공고 저장/발송 없음.

별도 요청으로 페이지당 15건 설정: 1페이지 15건, 2페이지 15건, 응답 페이지 번호 2, 두 페이지 ID 교집합 0. 두 번째 요청은 실제 pagingForm의 hidden 값을 POST했다.

생성한 첫 공고의 상세 URL: HTTP 200, 해당 공고 제목 포함. 사이트의 정상 빈 검색도 실제 확인했다. 구조와 요청 근거는 site-analysis.md에 기록했다.

임시 DB 경로를 지정한 실제 `--init`도 성공했다. 공고 63건, `initialized=true`, 알림 이력 0건을 `--status`로 확인했다. 같은 DB에 두 번째 `--init`은 종료 코드 2로 거부되었으며 기존 데이터는 보존되었다. 프로젝트 기본 DB는 초기화하지 않아 사용자 첫 실행의 무알림 동작을 유지한다.

고정 의존성의 `pip check`와 Python 소스 컴파일 검사도 통과했다. 응답에 보존된 검색 범위가 요청한 지역·기간·전체 상태·임대 유형과 다르면 저장하지 않도록 검증한다.

## Telegram 실제 검증 및 운영 제한

사용자가 기본 테스트 알림 수신을 확인했다. 이후 실제 공고 「[경기남부] 든든전세 매입임대주택 예비입주자 모집공고(비분양전환)」 1건으로 시험 메시지를 발송했고 Telegram API 성공 응답을 확인했다. 이 시험은 운영 DB와 발송 이력을 변경하지 않았다. 인증정보는 저장소에 포함하지 않는다. 전송 오류·429·중복 억제는 mock으로 검증했다.

운영체제 자동 실행 등록과 장시간 상시 실행은 사용자가 README에 따라 설정해야 한다. 이 작업에서 자동 실행 서비스나 예약 작업을 등록하지 않았다. 외부 API 성공 후 DB 기록 전 중단에 따른 중복 가능성은 남아 있으며 README에 명시했다.
